# Feature — Apply changes + signoff & baseline promotion (as built)

**Applies to:** `doc-hierarchy` (POC 2)
**Builds on:** `000.hackathon-doc-hierarchy.md` — that stays the base; this file is additive.
**Replaces:** `005.feature-apply-and-signoff.md` (original spec) and
`006.feature-apply-and-signoff-fine-tuning.md` (corrections). Both are folded in here.

Adds two things to the existing detect → trace → suggest → notify chain:
1. A document **owner accepts a suggestion and applies it** to the draft `.docx`.
2. Owners and reviewers **sign off**; once all are in, a **manager approves** and the draft
   becomes the next baseline, with `current-baseline.txt` repointed.

> **On code listings:** the original spec was written before the code existed and its listings
> did not survive contact with the compiler. Full listings below are only those confirmed
> correct as built. For modules that were rewritten, this file documents the API surface and
> semantics — **the source files are authoritative for their bodies.**

## Design decisions

### Applying changes

- **`apply_change` is a literal find-and-replace, not model-authored rewriting.** The owner
  approves a specific old→new text pair and the tool applies exactly that; it errors out if
  the old text isn't found rather than guessing. An LLM freely editing a signed-off
  engineering document is the one thing a safety-critical team would never accept.
- **Replacement reports its occurrence count.** `replaceText` returns how many matches it
  replaced — "800 metres" can appear in a heading as well as the body, and silently changing
  both while reporting nothing is how you lose track of what a document says.
- Known limitation: Word splits visible phrases across `<w:r>` runs, so a long fragment may
  not exist contiguously in `document.xml` — the error says to try a shorter fragment. (Docs
  generated by docx-js, like the samples, aren't fragmented, so this works out of the box.)

### Baselines are write-protected

`resolveDocPath` only confines paths to `docs/`, which includes frozen baselines. Since tool
arguments come from a model, a single bad path could silently rewrite a frozen audit record.
`resolveWritablePath` additionally rejects any first path segment matching `^baseline\d+$`.
**All mutating tools use it.**

### Signoffs are content-bound

The original design stored `{docId, name, role, date}` with no reference to *what* was signed,
so sign-off → edit → approve succeeded. As built, `SignoffState` gains
`approved: { docId, hash, date }[]`, and a document whose current hash no longer matches its
stored hash is treated as having **no** signoffs at all.

The hash is recorded **only when the owner+reviewer pair completes**, not per signoff. Hashing
at each signoff doesn't work: each signoff rewrites Status, so the second signoff's write
would invalidate the first one's hash. Writing it once, after the final Status/Signoff Date
update, avoids that entirely.

### Any edit restarts approval

`apply_change` calls `clearSignoffs`, which drops the document's signoffs *and* resets its
`Status` to `Draft — pending review` and `Signoff Date` to `TBD`. Two deliberate details:

- The reset happens **even when there were no signoffs to clear** — a document whose content
  changed must stop claiming `Approved — Baseline 1` regardless of its signoff history.
- It is a **no-op when the status is already draft**, so repeated edits don't rewrite the ZIP.

This also closes the window between the first and second signoff, where no hash exists yet.

### Signoff verifies identity against the document

`recordSignoff` rejects a name that doesn't match the document's declared `Owner`/`Reviewer`
cell, and refuses to sign a document that doesn't differ from the baseline. Still
assertion-based — **there is no real auth** — but it stops a reviewer recording an owner
signoff.

### Status is stamped at signoff, not at promotion

Rather than a bulk rewrite at promotion, the ladder is maintained as signoffs arrive:

```
Draft — pending review
  → first signoff   → "Owner signed off — pending reviewer"  (or Reviewer/owner)
  → pair completes  → "Approved — Baseline N", Signoff Date = today
```

`N` is `max(baselineN) + 1` computed at signoff time. **Assumption:** no baseline is created
between the last signoff and promotion, so this matches what `approveAndPromote` computes.
Holds with a single draft folder; goes stale if promotion never happens.

`DRAFT_STATUS` is a shared exported constant — the em dash must match byte-for-byte across
modules, and a hand-typed hyphen would create a second, near-identical status value.

### Promotion is guarded, not a rename button

`approve_baseline` refuses while any changed doc lacks owner *or* reviewer signoff. Only then
does it rename the draft to the next `baselineN` and repoint `current-baseline.txt`.
`signoffs.json` lives in the draft folder, so it freezes alongside the docs as an audit record.

### State mutations are serialized

MCP dispatches tool calls concurrently. Every state change is a read-modify-write of
`signoffs.json`, so overlapping calls lost each other's writes — observed directly: a reviewer
signoff completed before the owner signoff that was sent first, and `signoff_status`
subsequently reported the document unsigned. `signoff.ts` funnels `recordSignoff`,
`clearSignoffs`, and `approveAndPromote` through a promise-chain mutex. Single server process,
so an in-process queue is sufficient.

## Module API surface

### `metadata.ts`

```ts
export type DocMeta = { docId: string; owner: string; reviewer: string; dependsOn: string[] };

export async function readMetadata(filePath: string): Promise<DocMeta>;
export function findDocFile(dir: string, docId: string): string | null;
export function listDocFiles(dir: string): string[];
```

Parses the Field|Value table each document opens with (`Document ID`, `Title`, `Owner`,
`Reviewer`, `Depends On`, `Signoff Date`, `Status`).

**Keep the required-field guard.** Without it a malformed table throws
`TypeError: Cannot read properties of undefined (reading 'split')` instead of naming the
missing column.

`findDocFile` locates a draft file by matching each file's own `Document ID` cell — filenames
are not assumed to match document IDs.

### `applyChange.ts`

```ts
export function replaceText(file: string, oldText: string, newText: string): number;  // occurrence count
export function setMetadataField(file: string, field: string, value: string): void;
export function contentHash(file: string): string;                                    // SHA-256
```

Two traps, both confirmed by debugging:

- **`escapeXml` must NOT escape `>`.** XML text nodes don't require it and docx-js doesn't
  emit it, so any `oldText` containing `>` failed the match with a misleading "split across
  formatting runs" message.
  ```ts
  const escapeXml = (s: string) => s.replace(/&/g, "&amp;").replace(/</g, "&lt;");
  ```
- **`setMetadataField`'s tag pattern needs a whitespace guard:** `<w:t(\s[^>]*)?>`. Without
  the `\s`, `<w:t` also matches `<w:tc>` and `<w:tcPr>`, and the rewrite lands on the wrong tag.
  It matches the `<w:tr>` whose label cell is `field`, then swaps the following `<w:t>`.

### `signoff.ts`

```ts
export const DRAFT_STATUS: string;   // "Draft — pending review" — em dash, byte-exact

export type SignoffState = {
  draft: string;
  signoffs: { docId: string; name: string; role: "owner" | "reviewer"; date: string }[];
  approved: { docId: string; hash: string; date: string }[];
  approval: { manager: string; date: string } | null;
};

export function recordSignoff(draftDir, docId, name, role): Promise<string>;   // serialized
export function clearSignoffs(draftDir, docId): Promise<void>;                 // serialized
export function approveAndPromote(draftDir, manager): Promise<string>;         // serialized
export function pendingSignoffs(draftDir): Promise<PendingDoc[]>;
export function differsFromBaseline(draftFile: string): boolean;
```

### `currentBaseline.ts`

```ts
export const packageRoot: string;   // NOTE: named packageRoot, not PROJECT_ROOT
export function getCurrentBaselineDir(): string;
export function resolveDocPath(p: string): string;       // confines to docs/
export function resolveWritablePath(p: string): string;  // + rejects ^baseline\d+$
```

`resolveDocPath` is a module-local function in `mcpServer.ts` in the base plan — the earlier
claim that it was "already imported" was wrong.

### `ingest.ts`

`SearchClient` needs an explicit type argument — `new SearchClient<HierarchyDoc>(...)` —
otherwise `keyof TModel` resolves to `never` and `deleteDocuments("id", …)` fails with
*`"id"` is not assignable to `never`*.

## Tool surface (9 tools)

`list_documents`, `detect_change`, `trace_impact`, `suggest_changes`, `notify_owner`,
`apply_change`, `signoff`, `signoff_status`, `approve_baseline`.

### `list_documents` (new)

Discovery — without it the model cannot learn what folders or documents exist, and it supplies
the owner/reviewer names the signoff prompts need.

```
Current baseline: baseline1
Folders in docs/: baseline1, draft2

docs/draft2:
  SYS-REQ-001   CHANGED  Draft — pending review   owner: A. Chen  reviewer: M. Osei
  CMP-SIG-101   same     Approved — Baseline 1    owner: R. Fontaine  reviewer: M. Osei
```

### `detect_change` takes a document ID

As originally specified it declared `docId` and **ignored it**, requiring `baselinePath` and
`draftPath`. Nothing exposed the folder layout, so the model guessed paths, failed, and asked
the user for them — twice, in testing.

Now: `docId` + optional `draftDir`. Baseline resolved from `current-baseline.txt`, draft
located via `findDocFile`. Unknown IDs return `No document with ID X in draft2.`; a document
with no baseline copy reports as new.

### `apply_change`

```ts
inputSchema: {
  filePath: z.string().describe("Path to the DRAFT .docx to edit"),
  oldText:  z.string().describe("Exact existing text to replace"),
  newText:  z.string().describe("Replacement text"),
}
```
Resolves via `resolveWritablePath`, calls `replaceText`, then `clearSignoffs`. Returns the
occurrence count. Errors return `isError: true` with the message rather than throwing.

### `signoff` / `signoff_status` / `approve_baseline`

`signoff` takes `{ docId, name, role: "owner"|"reviewer", draftDir? }` and verifies `name`
against the document's own metadata. `signoff_status` lists changed documents still awaiting
either role. `approve_baseline` takes `{ manager, draftDir? }` and refuses while anything is
outstanding.

## Operational notes

- **Promotion is NOT recoverable via git.** `.gitignore` contains `**/docs/**`; only
  `.gitkeep` is tracked. A clean `git status` proves nothing about these files. Verify with
  `git ls-files` before assuming anything in `docs/` is recoverable.
- **Never `git clean` in `doc-hierarchy/`** to tidy test data — it deletes untracked source
  files. Use targeted removals.
- **Test against a disposable copy** (`docs/draft-test`), not `docs/draft2`.
- **Keep backups outside `docs/`.** A folder like `docs/draft2 - Copy` appears in
  `list_documents` and, not matching `^baseline\d+$`, is writable.
- **Restart the MCP client after any server code change.** `tsx` reads source once at process
  start; a running server keeps the old tool schemas. Claude Desktop must be **fully quit** —
  closing the window leaves the process alive.
- **`approve_baseline` really does rename the draft and rewrite `current-baseline.txt`**, so a
  successful run is not repeatable without restoring the sample folder.

## Demo script

```
List the documents in the draft.
```
```
SYS-REQ-001 changed in the draft. Trace what's affected, and for each
affected document show me the passage that needs updating.
```
```
I'm R. Fontaine, owner of CMP-SIG-101. Apply the braking distance update
to docs/draft2/CMP-SIG-101.docx and record my owner signoff.
```
```
What's still awaiting signoff?
```
```
I'm the engineering manager, D. Whitfield. Approve the baseline.
```

The last one **refuses** the first time, with signoffs outstanding — show that deliberately.
A workflow tool that can't say no isn't a workflow tool. Then collect the remaining signoffs
and re-run it.

Worth demonstrating alongside it: applying a change to an already-signed document drops its
signoffs and resets its Status, so `signoff_status` reopens it. That's change control working,
not a bug.

## Known limitations (unresolved)

- **`differsFromBaseline` compares raw bytes, and `adm-zip` rewrites the ZIP container.**
  Edit a value and change it back and the document still reads as CHANGED forever, because the
  container bytes moved. Observed in practice. Comparing extracted text would fix it.
- **`approveAndPromote` is not atomic** — `renameSync` then the pointer write. A failure
  between them leaves `current-baseline.txt` dangling.
- **One-shot lifecycle.** `draftDir` defaults to `docs/draft2`, which stops existing after
  promotion, and there is no "start the next draft" step.
- **No real identity.** Names are strings a caller asserts.
- **`chunk()` splits at a fixed 1000 chars**, mid-sentence once a document exceeds it, and
  embeds the metadata table along with the body.
