# Hackathon setup — Azure, workspace, `rag-api`

**Scope:** everything shared across POCs — Azure provisioning, the monorepo workspace, and the
one `rag-api` server every feature calls. No feature-specific tools, schemas, or ingest logic
live here; see `000.docs-search-init.md` and `000.doc-hierarchy-init.md` for those.

---

## Azure resources (already provisioned)

- Subscription: pay-as-you-go, prefix `hackathon-2026`
- `hackathon-2026-rg` — resource group
- `hackathon-2026-rag-search` — Azure AI Search, **free** SKU (3 indexes max, 50MB storage
  **shared across the whole service**, not per index)
- Endpoint: `https://hackathon-2026-rag-search.search.windows.net`
- Embedding model: **local**, `Xenova/all-MiniLM-L6-v2` via `@huggingface/transformers`
  (384 dims, no GPU, no Azure OpenAI quota wait) — used everywhere, no cloud embedding calls
- Two indexes on the one service: `docs-index`, `doc-hierarchy-index`

## Folder structure

```
hackathon/

├── .env                         # AZURE_SEARCH_ENDPOINT, AZURE_SEARCH_KEY (shared)
├── rag-api/
│   └── src/{embed.ts, ragApi.ts}      # generic vector search ONLY — no schema, no business fields
├── docs-search/                 # POC 1 — see 000.docs-search-init.md
├── doc-hierarchy/                # POC 2 — see 000.doc-hierarchy-init.md
└── wiki-freshness/               # reserved — the original ADO staleness idea, not started
```

**Root `package.json`** — each feature workspace defines its own scripts (`create-index`,
`ingest`, `mcp`); this just delegates to them so nothing needs a `cd`:
```json
{
  "name": "hackathon",
  "private": true,
  "workspaces": ["rag-api", "docs-search", "doc-hierarchy"],
  "scripts": {
    "rag-api:start": "npm run start -w rag-api",
    "docs-search:create-index": "npm run create-index -w docs-search",
    "docs-search:ingest": "npm run ingest -w docs-search",
    "doc-hierarchy:create-index": "npm run create-index -w doc-hierarchy",
    "doc-hierarchy:ingest": "npm run ingest -w doc-hierarchy"
  }
}
```

**Root `.env`** (read by `rag-api` and each feature's `createIndex.ts`/`ingest.ts` — all
anchored to this exact path rather than the default `dotenv/config` cwd lookup; see the note
under `rag-api/src/ragApi.ts` for why):
```
AZURE_SEARCH_ENDPOINT=https://hackathon-2026-rag-search.search.windows.net
AZURE_SEARCH_KEY=<admin-key>
```

**`.gitignore`** — every feature's `docs/` folder is test/sample data, not source:
```
**/docs/**
!**/docs/.gitkeep
```
This means **nothing under any `docs/` folder is recoverable from git** — a clean `git status`
only proves no *tracked* file changed. Worth keeping in mind everywhere `docs/` comes up in the
feature docs:
- Verify with `git ls-files <path>` before assuming a file is backed up.
- Never `git clean` inside a feature's package — it removes untracked source right alongside
  test data.
- Keep a copy of any `docs/` folder outside the repo before an operation you'd hate to lose
  (e.g. promoting a `doc-hierarchy` baseline).

## Key design decisions (and why)

- **One `rag-api`, not one per POC.** It only knows "embed a query, search an index, apply a
  filter." It has no schema and no opinion on business fields — each feature's own
  `createIndex.ts` owns its schema and passes its index name per-request.
- **`embed()` is duplicated, not imported, into each feature's `ingest.ts`.** Cheap duplication
  beats cross-workspace import friction mid-hackathon. Same reasoning applies to
  `createIndex.ts` — no shared schema file.
- **MCP servers are local stdio processes** (`@modelcontextprotocol/sdk`, `McpServer` +
  `StdioServerTransport`), run via `npx tsx src/mcpServer.ts` and registered directly in
  LM Studio / Claude Desktop's `mcp.json` — not a hosted option like Azure Functions, which
  doesn't fit a local-first hackathon build.
- **Every `ingest.ts` uses deterministic, content-derived IDs and deletes a document's existing
  chunks before re-uploading them.** Random IDs would mean re-ingesting the same document (a
  re-run, a new version) piles up duplicates and leaves orphaned chunks behind when content
  shrinks. What "the same document" means differs per feature — `doc-hierarchy` keys on
  `docId`, `docs-search` keys on file path — but the pattern is identical.
- **Paths resolve against each package's own root** (`fileURLToPath(new URL("..",
  import.meta.url))`), never `process.cwd()`, and `.env` is loaded from an explicit path
  anchored to the monorepo root rather than the default cwd-relative lookup. Both matter for
  the same reason: npm workspace scripts and MCP clients don't run scripts from inside the
  package directory, so anything resolved against `cwd` breaks depending on how it's launched.
- **`embed()` caches the in-flight model-load promise, not the resolved pipeline.** A caller
  doing `Promise.all` over several chunks would otherwise have every call race past a
  resolved-value check before the first load finishes, each starting its own ~80MB model load.
  This applies everywhere `embed()` is duplicated to, including inside `rag-api` itself — a
  single incoming request never needed this, but two `/search` calls landing during a cold
  start would each trigger their own load without it.
- **`RAG_API_URL` is read from an environment variable with a localhost default**, not
  hardcoded, in every MCP server that calls it.

## Open decisions (not yet settled)

- **Which POC becomes the actual hackathon submission** — deliberately deferred. Plan is to

## `rag-api` — generic vector search server

**`rag-api/src/embed.ts`**
```ts
import { pipeline, type FeatureExtractionPipeline } from "@huggingface/transformers";

// Cache the in-flight promise, not the resolved pipeline — see the design note above.
let extractorPromise: Promise<FeatureExtractionPipeline> | undefined;

export async function embed(text: string): Promise<number[]> {
  extractorPromise ??= pipeline("feature-extraction", "Xenova/all-MiniLM-L6-v2");
  const extractor = await extractorPromise;
  return Array.from((await extractor(text, { pooling: "mean", normalize: true })).data as Float32Array);
}
```

**`rag-api/src/ragApi.ts`**
```ts
import { config } from "dotenv";
// Anchored to the monorepo root, not process.cwd() — the default `dotenv/config` lookup
// only finds .env when the process happens to be launched from hackathon/.
config({ path: new URL("../../.env", import.meta.url) });

import express from "express";
import { SearchClient, AzureKeyCredential } from "@azure/search-documents";
import { embed } from "./embed.js";

const credential = new AzureKeyCredential(process.env.AZURE_SEARCH_KEY!);
const clients = new Map<string, SearchClient<any>>();
function getClient(index: string) {
  if (!clients.has(index)) clients.set(index, new SearchClient(process.env.AZURE_SEARCH_ENDPOINT!, index, credential));
  return clients.get(index)!;
}

const app = express();
app.use(express.json());

app.post("/search", async (req, res) => {
  const { index, query, top_k = 5, filter } = req.body as { index: string; query: string; top_k?: number; filter?: string };
  if (!index) return res.status(400).json({ error: "'index' is required" });
  const vector = await embed(query);
  const results = await getClient(index).search("*", {
    vectorSearchOptions: { queries: [{ kind: "vector", vector, fields: ["embedding"], kNearestNeighborsCount: top_k }] },
    filter,
  });
  const hits: any[] = [];
  for await (const r of results.results) hits.push({ ...r.document, score: r.score });
  res.json({ results: hits });
});

app.listen(process.env.PORT ?? 8000, () => console.log(`RAG API on :${process.env.PORT ?? 8000}`));
```

**`rag-api/package.json`**:
```json
{
  "name": "rag-api",
  "private": true,
  "type": "module",
  "scripts": { "start": "tsx src/ragApi.ts" }
}
```

## Install and run (shared foundation)

```bash
cd hackathon
npm install express @azure/search-documents @huggingface/transformers dotenv -w rag-api
npm install -D typescript tsx @types/node @types/express   # shared dev tooling, once at the root

# leave running throughout — every feature calls this
npm run rag-api:start
```

Each feature doc's own install/run steps assume this is already done. MCP servers get
registered per feature, but end up side by side in the same `mcp.json`:
```json
{
  "mcpServers": {
    "docs-search": { "command": "npx", "args": ["tsx", "/absolute/path/hackathon/docs-search/src/mcpServer.ts"] },
    "doc-hierarchy": { "command": "npx", "args": ["tsx", "/absolute/path/hackathon/doc-hierarchy/src/mcpServer.ts"] }
  }
}
```
