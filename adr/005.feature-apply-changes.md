# 005 — `apply_change`: native Word tracked changes

**Scope:** `doc-hierarchy` only. Covers *proposing* an edit as a native Word tracked change.
**Explicitly deferred:** signoff (author signoff and reviewer signoff are both required, per
discussion — not built here), promoting a draft to a baseline, and flattening/accepting
revisions into clean text. Those need their own doc once this is solid; nothing here should be
read as implying they're settled.
**Relates to:** `004.doc-hierarchy-dynamic-baselines.md` — this builds on `baselines.ts`'s
`getLatestBaselineDir()`/`getLatestDraftDir()`, not the older `current-baseline.txt` scheme.

**The idea:** an owner (or the agent acting for them) applies a suggested edit to a draft
document. The edit lands as a real Word tracked change — `<w:ins>`/`<w:del>` in the actual
OOXML — authored as that document's declared `Owner`. A reviewer opens the file in Word,
sees native red/underline markup, and uses Word's own Accept/Reject. Nothing about that last
step touches our tools at all.

---

## Why a draft is already a "clean slate" for this

A draft starts as a byte-for-byte copy of its baseline. At that moment it has zero tracked
changes, by construction — nothing new is needed to get that property. As `apply_change` calls
land over the draft's lifetime, the tracked changes accumulate inside the file itself, visible
to anyone who opens it in Word. When a draft is eventually promoted (out of scope here), a
fresh draft starts the cycle over as a clean copy again. The revision boundary and the baseline
boundary are the same boundary — nothing to build there, just something to rely on.

## Key design decisions (and why)

- **`apply_change` operates on whole paragraphs only** — replace paragraph text, not
  sub-paragraph edits. This matches `detect_change`'s existing granularity (`diffLines`, not
  `diffWords`), and it's what keeps the OOXML surgery bounded: wrap one paragraph's runs in
  `<w:del>`, insert one new paragraph wrapped in `<w:ins>` right after. Inserting a brand new
  paragraph where none existed, or deleting one outright with no replacement, are both out of
  scope for this version.
- **The target paragraph is identified by its exact current text, not by index or line
  number.** The caller supplies the paragraph's current text as `oldText`; `apply_change` finds
  it and refuses if it isn't found, or if it matches more than one paragraph. This is the same
  shape as any "find-and-replace, unique match required" tool — ambiguity is a refusal, not a
  guess. It also means a stale or already-superseded `oldText` fails loudly instead of silently
  editing the wrong spot.
- **The revision's author is the document's own declared `Owner`, read from its metadata table
  at the moment of the edit — never a caller-supplied string.** The model can't put an arbitrary
  name on a tracked change; it's always attributed to whoever the document says owns it.
- **A second `apply_change` call against the same `oldText` updates the pending proposal in
  place, rather than stacking a second tracked change on top of an unreviewed one.** Concretely:
  if the text you're targeting turns out to already be the *deleted* side of a proposal
  `apply_change` made earlier (paragraph wrapped in `<w:del>`, immediately followed by our
  pending `<w:ins>`), the pending insertion's text gets revised instead of creating a new
  del/ins pair. That content isn't "real" yet — reviising a draft-of-a-draft is fine; stacking
  revisions on top of each other isn't.
- **`apply_change` only ever writes into the latest draft**, never a baseline — baselines stay
  frozen, matching every other write path in this project so far.
- **`parseMetadata` moves out of `ingest.ts` into its own `metadata.ts`.** Both `ingest.ts` and
  `applyChange.ts` need to agree on exactly what "the metadata table" means; duplicating that
  parsing logic risks the two silently drifting apart.
- **OOXML is manipulated with a real XML parser (`xmldom` + `xpath`), not regex.** `parseMetadata`
  gets away with regex because it operates on `mammoth`'s already-simplified HTML. Raw
  `word/document.xml` is a different animal — visible text is routinely split across multiple
  `<w:r>` runs even when nothing looks formatted, namespaces are everywhere, and getting that
  wrong silently corrupts the file rather than throwing. A DOM gives us paragraph-by-paragraph
  structure to walk reliably.

---

## How Word tracked changes actually work (so the code below makes sense)

A `.docx` is a zip archive; the content lives in `word/document.xml`. Word doesn't compute
"what changed" when it opens a file — trackedness is baked into the XML itself, or it isn't
there at all. The relevant pieces:

- A **deleted run** wraps its text in `<w:del>`, and the text element itself becomes
  `<w:delText>` instead of the normal `<w:t>`:
  ```xml
  <w:del w:id="1" w:author="A. Chen" w:date="2026-09-15T10:00:00Z">
    <w:r><w:delText xml:space="preserve">Maximum braking distance: 800m.</w:delText></w:r>
  </w:del>
  ```
- An **inserted run** wraps its text in `<w:ins>`, keeping the normal `<w:t>`:
  ```xml
  <w:ins w:id="2" w:author="A. Chen" w:date="2026-09-15T10:00:00Z">
    <w:r><w:t xml:space="preserve">Maximum braking distance: 750m.</w:t></w:r>
  </w:ins>
  ```
- Marking an **entire paragraph** (not just some text inside it) as inserted or deleted also
  needs the paragraph mark itself flagged, via `<w:pPr><w:rPr>`:
  ```xml
  <w:pPr><w:rPr><w:ins w:id="3" w:author="A. Chen" w:date="..."/></w:rPr></w:pPr>
  ```
  This is what tells Word the whole paragraph — including its line break — is part of the
  revision, not just the text inside it.
- Every `w:ins`/`w:del` needs a document-wide-unique `w:id`.

A "replace this paragraph" edit is therefore: wrap the *existing* paragraph's runs in `<w:del>`
(with the paragraph-mark `<w:rPr><w:del/></w:rPr>` too), and insert a *new* `<w:p>` right after
carrying the new text, marked as an insertion the same way.

## `doc-hierarchy/src/metadata.ts` (new — extracted from `ingest.ts`)

```ts
import mammoth from "mammoth";

export type DocMetadata = {
  docId: string;
  owner: string;
  reviewer: string;
  dependsOn: string[];
};

// Every doc starts with a Field | Value table: Document ID, Title, Owner,
// Reviewer, Depends On, Signoff Date, Status.
export function parseMetadata(html: string): DocMetadata {
  const rows = [...html.matchAll(/<tr>(.*?)<\/tr>/gs)].map(m =>
    [...m[1].matchAll(/<td[^>]*>(.*?)<\/td>/gs)].map(c => c[1].replace(/<[^>]+>/g, "").trim())
  );
  const map = Object.fromEntries(rows.map(([k, v]) => [k, v]));

  const required = ["Document ID", "Owner", "Reviewer", "Depends On"] as const;
  const missing = required.filter(f => map[f] === undefined);
  if (missing.length) {
    throw new Error(`Metadata table missing field(s): ${missing.join(", ")}`);
  }

  return {
    docId: map["Document ID"],
    owner: map["Owner"],
    reviewer: map["Reviewer"],
    dependsOn: map["Depends On"] === "—" ? [] : map["Depends On"].split(",").map(s => s.trim()),
  };
}

export async function readDocMetadata(filePath: string): Promise<DocMetadata> {
  const { value: html } = await mammoth.convertToHtml({ path: filePath });
  return parseMetadata(html);
}
```

}

enough on its own, no extra check needed.

## `doc-hierarchy/src/applyChange.ts` (new)

```ts
import fs from "node:fs";
import JSZip from "jszip";
import { DOMParser, XMLSerializer } from "@xmldom/xmldom";
import xpath from "xpath";

const W_NS = "http://schemas.openxmlformats.org/wordprocessingml/2006/main";
const select = xpath.useNamespaces({ w: W_NS });

function xmlEscape(text: string): string {
  return text
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;");
}

function visibleText(paragraph: Node): string {
  return (select(".//w:t", paragraph) as Node[]).map(n => n.textContent ?? "").join("");
}

function deletedText(paragraph: Node): string {
  return (select(".//w:delText", paragraph) as Node[]).map(n => n.textContent ?? "").join("");
}

function isParagraphInsertion(paragraph: Node): boolean {
  return (select("./w:pPr/w:rPr/w:ins", paragraph) as Node[]).length > 0;
}

function isParagraphDeletion(paragraph: Node): boolean {
  return (select("./w:pPr/w:rPr/w:del", paragraph) as Node[]).length > 0;
}

function nextRevisionId(doc: Document): number {
  const ids = (select("//w:ins/@w:id | //w:del/@w:id", doc) as Attr[])
    .map(a => Number(a.value))
    .filter(n => Number.isFinite(n));
  return (ids.length ? Math.max(...ids) : 0) + 1;
}

function parseFragment(xml: string): Node {
  return new DOMParser().parseFromString(xml, "text/xml").documentElement!;
}

/**
 * Replace the paragraph whose current text is exactly `oldText` with `newText`,
 * as a native Word tracked change. If `oldText` matches a paragraph this function
 * already turned into a pending proposal (an unreviewed <w:ins> paragraph whose
 * preceding <w:del> holds `oldText`), the pending proposal's text is revised in
 * place instead of stacking a second tracked change.
 */
export async function applyChange(filePath: string, oldText: string, newText: string, author: string): Promise<void> {
  const zip = await JSZip.loadAsync(fs.readFileSync(filePath));
  const docXmlPath = "word/document.xml";
  const xml = await zip.file(docXmlPath)!.async("string");
  const doc = new DOMParser().parseFromString(xml, "text/xml");

  const paragraphs = select("//w:body/w:p", doc) as Node[];

  const freshMatches = paragraphs.filter(p =>
    !isParagraphInsertion(p) && !isParagraphDeletion(p) && visibleText(p) === oldText
  );

  const pendingMatches: { del: Node; ins: Node }[] = [];
  paragraphs.forEach((p, i) => {
    if (isParagraphDeletion(p) && deletedText(p) === oldText) {
      const next = paragraphs[i + 1];
      if (next && isParagraphInsertion(next)) pendingMatches.push({ del: p, ins: next });
    }
  });

  const total = freshMatches.length + pendingMatches.length;
  if (total === 0) {
    throw new Error(
      `No paragraph matching the given text was found in ${filePath}. It may already have a ` +
      `different proposal pending, or the text doesn't match exactly.`
    );
  }
  if (total > 1) {
    throw new Error(`The given text matches more than one paragraph in ${filePath} — use a longer, unique excerpt.`);
  }

  const date = new Date().toISOString();

  if (pendingMatches.length === 1) {
    const { ins } = pendingMatches[0];
    (select(".//w:r", ins) as Node[]).forEach(r => r.parentNode?.removeChild(r));
    const runNode = parseFragment(
      `<w:r xmlns:w="${W_NS}"><w:t xml:space="preserve">${xmlEscape(newText)}</w:t></w:r>`
    );
    ins.appendChild(doc.importNode(runNode, true));
  } else {
    const original = freshMatches[0];
    const delId = nextRevisionId(doc);

    const newPPr = parseFragment(
      `<w:pPr xmlns:w="${W_NS}"><w:rPr><w:del w:id="${delId}" w:author="${xmlEscape(author)}" w:date="${date}"/></w:rPr></w:pPr>`
    );
    const existingPPr = (select("./w:pPr", original) as Node[])[0];
    if (existingPPr) original.replaceChild(doc.importNode(newPPr, true), existingPPr);
    else original.insertBefore(doc.importNode(newPPr, true), original.firstChild);

    (select(".//w:r", original) as Node[]).forEach(r => {
      const text = (select(".//w:t", r) as Node[]).map(n => n.textContent ?? "").join("");
      const delRun = parseFragment(
        `<w:del xmlns:w="${W_NS}" w:id="${nextRevisionId(doc)}" w:author="${xmlEscape(author)}" w:date="${date}">` +
        `<w:r><w:delText xml:space="preserve">${xmlEscape(text)}</w:delText></w:r></w:del>`
      );
      r.parentNode?.replaceChild(doc.importNode(delRun, true), r);
    });

    const insId = nextRevisionId(doc);
    const insPara = parseFragment(
      `<w:p xmlns:w="${W_NS}">` +
      `<w:pPr><w:rPr><w:ins w:id="${insId}" w:author="${xmlEscape(author)}" w:date="${date}"/></w:rPr></w:pPr>` +
      `<w:ins w:id="${insId + 1}" w:author="${xmlEscape(author)}" w:date="${date}">` +
      `<w:r><w:t xml:space="preserve">${xmlEscape(newText)}</w:t></w:r></w:ins>` +
      `</w:p>`
    );
    original.parentNode!.insertBefore(doc.importNode(insPara, true), original.nextSibling);
  }

  const updatedXml = new XMLSerializer().serializeToString(doc);
  zip.file(docXmlPath, updatedXml);
  fs.writeFileSync(filePath, await zip.generateAsync({ type: "nodebuffer" }));
}
```

## `doc-hierarchy/src/mcpServer.ts` — new tool

```ts
import { readDocMetadata } from "./metadata.js";
import { applyChange } from "./applyChange.js";
import { draftFilePath } from "./baselines.js";

server.registerTool(
  "apply_change",
  {
    description: "Propose a tracked-change edit to a paragraph in the current draft, authored as the document's owner. Reviewable natively in Word — doesn't touch accepted text until someone reviews the revision.",
    inputSchema: { docId: z.string(), oldText: z.string(), newText: z.string() },
  },
  async ({ docId, oldText, newText }) => {
    const filePath = draftFilePath(docId);
    const { owner } = await readDocMetadata(filePath);
    await applyChange(filePath, oldText, newText, owner);
    return { content: [{ type: "text" as const, text: `Proposed change to ${docId}, tracked as an edit by ${owner}.` }] };
  }
);
```

## Known risks — validate before relying on this

This is a first-pass implementation of something genuinely fiddly. Specifically unverified:

- **XML round-trip fidelity.** Parsing `word/document.xml` with `@xmldom/xmldom` and
  re-serializing it needs to produce something Word still opens cleanly — namespace handling
  and attribute ordering across DOM implementations can be inconsistent. Test: run
  `apply_change` against a real sample doc, then actually open the result in Word (or
  LibreOffice) and confirm it opens without a repair prompt and shows the edit in the Reviewing
  pane.
- **Whether Word actually recognizes the revision as valid**, not just whether the file opens —
  confirm Accept/Reject works on the specific paragraph-mark + run-level structure generated
  here.
- **`mammoth`'s behavior against a document with pending tracked changes** — unverified whether
  `extractRawText`/`convertToHtml` include inserted text, exclude deleted text, or do something
  else entirely once `<w:ins>`/`<w:del>` are present. This affects what `detect_change` and
  `list_documents` report once a draft has unreviewed proposals in it — worth an explicit test
  rather than assuming.
- **Multiple sequential `apply_change` calls on different paragraphs in the same file** — each
  call reopens and rewrites the whole zip, so this should be fine, but hasn't been exercised
  more than once in a row.

## Explicitly not covered here

- Detecting that a reviewer accepted or rejected a revision in Word.
- Author signoff and reviewer signoff (both required, per the discussion this doc followed from)
  — next doc's problem.
- Promoting a draft to a baseline, and flattening any *remaining* accepted-but-unflattened
  revisions into clean text as part of that.
