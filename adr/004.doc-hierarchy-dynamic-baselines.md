# 004 — dynamic `baseline-<N>` / `draft-<N>` resolution

**Scope:** `doc-hierarchy` only, same as prior docs in this series.
**Relates to:** `003.doc-hierarchy-behavior-briefing.md` (the as-built snapshot this plan
updates). Two changes requested directly, plus a gap tracker carried over from the review of
`003`.

1. Folder naming becomes `baseline-<N>` / `draft-<N>` instead of ad hoc names (`baseline1`,
   `draft2`).
2. Nothing hardcodes a specific folder name any more. The **highest-numbered** `baseline-<N>`
   and `draft-<N>` folders under `docs/` are resolved dynamically wherever "current baseline"
   or "the draft to compare against" was previously a literal string or a pointer file.

`current-baseline.txt` is removed entirely — there's no longer a separate "promoted" pointer to
keep in sync; the highest index *is* current.

**Indexing is single-baseline, on purpose.** Nothing in the current 5-tool surface ever needs
the search index to hold more than one baseline's content — `suggest_changes` and
`trace_impact` only ever consult the latest baseline, and `detect_change`/`list_documents`
never touch the index at all (they diff `.docx` files directly). So `ingest.ts` always targets
the latest baseline and always wipes the index first — there's no folder argument to index a
draft separately any more, and no `baseline` field in the schema. Indexing scoped to coexist
across multiple baselines is a real feature to consider later, not built now — if that need
shows up, it should be added deliberately (a `baseline` field, per-baseline filters), not
reappear as an accidental byproduct of something else.

## Gap tracker (from the `003` review)

| # | Gap | Status |
|---|---|---|
| 1 | Chunk IDs and stale-chunk cleanup in `ingest.ts` were keyed on `docId` only, with no way to know which baseline a chunk belonged to — indexing `draft2` for any reason would silently overwrite `baseline1`'s chunks for a shared `docId`. | **Fixed here — simplified, not baseline-scoped.** Since the index is only ever meant to hold one baseline's content, `ingest.ts` now always targets the latest baseline and wipes the whole index before reindexing it. No `baseline` field, no per-baseline filter, no way to accidentally index a draft into the shared index at all. |
| 2 | `manifest.json` was specified (in the `000`-era plan) to be generated by `ingest.ts`, but `003` shows it's still separately authored. | **Fixed here** — generated as part of the same ingest run, validated before the index is touched (see §2). |
| 3 | `detect_change`'s schema requires `docId` but the handler ignores it, still requiring explicit `baselinePath`/`draftPath`. | **Resolved as a corollary** of dynamic resolution — `docId` now drives the default paths when explicit ones aren't given. |
| 4 | `downstreamOf` tolerates a cyclic `dependsOn` graph silently. | **Partially addressed** — `ingest.ts` now rejects a cycle before writing `manifest.json` at all, which matters more now that the manifest is generated automatically rather than hand-authored (no human proofreading step in between a typo'd "Depends On" cell and a broken graph). `downstreamOf` itself is unchanged. |

| 6 | `rag-api`'s `/search` has no relevance floor, so "`SUB-TRAC-020` is unaffected" still depends on the calling model reading raw kNN scores live. | **Still open.** |
| 7 | `list_documents` (byte-for-byte `.docx` comparison) and `detect_change` (`mammoth`-extracted text diff) can disagree on whether a doc "changed", since Word rewrites internal XML on every save regardless of visible content. | **Still open** — needs a decision on which method is authoritative, not a path-resolution fix. |

## 1. Folder naming and resolution

```
docs/
├── baseline-1/        # was: baseline1
│   └── manifest.json  # now written by ingest.ts, not hand-authored
├── draft-1/            # was: draft2 — numbering restarts at 1 for drafts specifically,
│                        # since draft numbering tracks candidate iterations, not a shared
│                        # counter with baselines
└── ...
```

Numeric, not lexicographic, ordering — `baseline-10` must outrank `baseline-9`, which a plain
string sort would get wrong.

**`doc-hierarchy/src/baselines.ts`** — renamed from `currentBaseline.ts`; the old name implied
a "current" pointer that no longer exists.
```ts
import fs from "node:fs";
import path from "node:path";
import { fileURLToPath } from "node:url";

// src/ -> package root. Independent of whatever cwd the MCP client uses.
export const packageRoot = fileURLToPath(new URL("..", import.meta.url));
const docsRoot = path.join(packageRoot, "docs");

function latestNumberedDir(kind: "baseline" | "draft"): string {
  const pattern = new RegExp(`^${kind}-(\\d+)$`);
  const entries = fs.existsSync(docsRoot) ? fs.readdirSync(docsRoot, { withFileTypes: true }) : [];
  const matches = entries
    .filter(e => e.isDirectory())
    .map(e => ({ name: e.name, match: e.name.match(pattern) }))
    .filter((e): e is { name: string; match: RegExpMatchArray } => e.match !== null)
    .map(e => ({ name: e.name, index: Number(e.match[1]) }));

  if (matches.length === 0) {
    throw new Error(`No ${kind}-<N> folders found under ${docsRoot}`);
  }
  matches.sort((a, b) => b.index - a.index);
  return path.join(docsRoot, matches[0].name);
}

/** Highest-numbered docs/baseline-<N> folder. There's no separate "promoted" pointer any
 * more — the highest index is authoritative. */
export function getLatestBaselineDir(): string {
  return latestNumberedDir("baseline");
}

/** Highest-numbered docs/draft-<N> folder — the default candidate to diff against. */
export function getLatestDraftDir(): string {
  return latestNumberedDir("draft");
}

/**
 * Resolve a caller-supplied path against the package root, and refuse anything that
 * resolves outside docs/. These paths come from whatever the calling model supplies via
 * an MCP tool call, not just from you.
 */
export function resolveDocPath(p: string): string {
  const resolved = path.isAbsolute(p) ? path.resolve(p) : path.resolve(packageRoot, p);
  const resolvedDocsRoot = path.resolve(docsRoot);
  if (resolved !== resolvedDocsRoot && !resolved.startsWith(resolvedDocsRoot + path.sep)) {
    throw new Error(`Path escapes docs/: ${p}`);
  }
  return resolved;
}
```

## 2. `ingest.ts` — always the latest baseline, wipe-then-reindex, validate first

Two structural changes from the previous draft of this doc:

- **No folder argument any more.** `ingest.ts` always targets `getLatestBaselineDir()`. There's
  no supported way to index a draft into the shared index — see the note at the top of this
  document on why that's deliberate, not an oversight.
- **The whole index is wiped before reindexing**, so a stale entry from a previous baseline (or
  from before this change, under the old ID scheme) can never linger. This replaces the manual
  "drop and recreate the index" step entirely — running `ingest.ts` is now sufficient on its
  own.
- **All documents are parsed and validated *before* anything is wiped.** With the old
  per-document stale-delete pattern, a malformed doc partway through the loop would just leave
  earlier docs indexed and later ones untouched. With an upfront wipe, that same failure mode
  would leave the index wiped but only half-repopulated — worse. Parsing everything first and
  failing fast avoids ever wiping the index unless every document in the baseline is already
  known-good.

```ts
import { config } from "dotenv";
config({ path: new URL("../../.env", import.meta.url) });

import fs from "node:fs";
import path from "node:path";
import mammoth from "mammoth";
import { pipeline, type FeatureExtractionPipeline } from "@huggingface/transformers";
import { SearchClient, AzureKeyCredential } from "@azure/search-documents";
import { getLatestBaselineDir, packageRoot } from "./baselines.js";

type HierarchyDoc = {
  id: string;
  docId: string;
  content: string;
  source: string;
  owner: string;
  reviewer: string;
  dependsOn: string[];
  embedding: number[];
};

type ParsedDoc = {
  filePath: string;
  text: string;
  docId: string;
  owner: string;
  reviewer: string;
  dependsOn: string[];
};

const client = new SearchClient<HierarchyDoc>(
  process.env.AZURE_SEARCH_ENDPOINT!, "doc-hierarchy-index",
  new AzureKeyCredential(process.env.AZURE_SEARCH_KEY!)
);

let extractorPromise: Promise<FeatureExtractionPipeline> | undefined;
async function embed(text: string): Promise<number[]> {
  extractorPromise ??= pipeline("feature-extraction", "Xenova/all-MiniLM-L6-v2");
  const extractor = await extractorPromise;
  return Array.from((await extractor(text, { pooling: "mean", normalize: true })).data as Float32Array);
}

// Every doc starts with a Field | Value table: Document ID, Title, Owner,
// Reviewer, Depends On, Signoff Date, Status.
function parseMetadata(html: string) {
  const rows = [...html.matchAll(/<tr>(.*?)<\/tr>/gs)].map(m =>
    [...m[1].matchAll(/<td[^>]*>(.*?)<\/td>/gs)].map(c => c[1].replace(/<[^>]+>/g, "").trim())
  );
  const map = Object.fromEntries(rows.map(([k, v]) => [k, v]));

  const required = ["Document ID", "Owner", "Reviewer", "Depends On"] as const;
  const missing = required.filter(f => map[f] === undefined);
  if (missing.length) {
    throw new Error(`Metadata table missing field(s): ${missing.join(", ")}`);
  }

  return {
    docId: map["Document ID"],
    owner: map["Owner"],
    reviewer: map["Reviewer"],
    dependsOn: map["Depends On"] === "—" ? [] : map["Depends On"].split(",").map(s => s.trim()),
  };
}

function chunk(text: string, size = 1000): string[] {
  const out: string[] = [];
  for (let i = 0; i < text.length; i += size) out.push(text.slice(i, i + size));
  return out;
}

async function parseFile(filePath: string): Promise<ParsedDoc> {
  const { value: html } = await mammoth.convertToHtml({ path: filePath });
  const { value: text } = await mammoth.extractRawText({ path: filePath });
  const meta = parseMetadata(html);
  return { filePath, text, ...meta };
}

function assertNoCycle(manifest: { docId: string; dependsOn: string[] }[]) {
  const dependsOnById = new Map(manifest.map(m => [m.docId, m.dependsOn]));
  const state = new Map<string, "visiting" | "done">();

  function visit(id: string, chain: string[]) {
    if (state.get(id) === "done") return;
    if (state.get(id) === "visiting") {
      throw new Error(`Dependency cycle: ${[...chain, id].join(" -> ")}`);
    }
    state.set(id, "visiting");
    for (const dep of dependsOnById.get(id) ?? []) visit(dep, [...chain, id]);
    state.set(id, "done");
  }

  for (const { docId } of manifest) visit(docId, []);
}

// Wipes every document currently in the index — not the Azure Search index resource itself,
// just its contents. Since the index only ever represents one baseline at a time, this is
// sufficient to guarantee no stale entry from a previous run (or a previous ID scheme) survives.
async function wipeIndex() {
  let ids: string[];
  try {
    const all = await client.search("*", { select: ["id"] });
    ids = [];
    for await (const r of all.results) ids.push(r.document.id);
  } catch (err) {
    throw new Error(
      `Could not read doc-hierarchy-index — has createIndex.ts been run yet? (${(err as Error).message})`
    );
  }
  if (ids.length) await client.deleteDocuments("id", ids);
  console.log(`Wiped ${ids.length} existing chunk(s) from the index before reindexing.`);
}

async function uploadDoc(doc: ParsedDoc) {
  const chunks = chunk(doc.text);
  const documents = await Promise.all(chunks.map(async (c, i) => ({
    id: `${doc.docId}-${i}`,
    docId: doc.docId,
    content: c,
    source: path.relative(packageRoot, doc.filePath).split(path.sep).join("/"),
    owner: doc.owner,
    reviewer: doc.reviewer,
    dependsOn: doc.dependsOn,
    embedding: await embed(c),
  })));
  await client.uploadDocuments(documents);
  console.log(`Indexed ${documents.length} chunks from ${doc.docId}`);
}

const baselineDir = getLatestBaselineDir();
const files = fs.readdirSync(baselineDir).filter(f => f.endsWith(".docx"));

// Parse and validate every document before touching the index — a malformed doc found
// partway through must not leave the index wiped but only half-repopulated.
const parsed = await Promise.all(files.map(f => parseFile(path.join(baselineDir, f))));
const manifest = parsed.map(d => ({ docId: d.docId, dependsOn: d.dependsOn }));
assertNoCycle(manifest);

await wipeIndex();
for (const doc of parsed) await uploadDoc(doc);

fs.writeFileSync(path.join(baselineDir, "manifest.json"), JSON.stringify(manifest, null, 2));
console.log(`Wrote manifest.json (${manifest.length} docs) to ${baselineDir}`);
```
Run: `npm run doc-hierarchy:ingest` — always resolves to the highest-numbered `baseline-<N>`,
wipes the index, reindexes, and rewrites that folder's `manifest.json`. No arguments needed or
accepted.

## 3. `createIndex.ts` — no schema change needed

The as-built schema in `003` never had a `baseline` field, so nothing here changes. Keep it as
is:
```ts
import { config } from "dotenv";
config({ path: new URL("../../.env", import.meta.url) });

import { SearchIndexClient, AzureKeyCredential, SearchIndex } from "@azure/search-documents";

const client = new SearchIndexClient(process.env.AZURE_SEARCH_ENDPOINT!, new AzureKeyCredential(process.env.AZURE_SEARCH_KEY!));

const index: SearchIndex = {
  name: "doc-hierarchy-index",
  fields: [
    { name: "id", type: "Edm.String", key: true },
    { name: "docId", type: "Edm.String", filterable: true },
    { name: "content", type: "Edm.String", searchable: true },
    { name: "source", type: "Edm.String", filterable: true },
    { name: "owner", type: "Edm.String", filterable: true },
    { name: "reviewer", type: "Edm.String", filterable: true },
    { name: "dependsOn", type: "Collection(Edm.String)", filterable: true },
    { name: "embedding", type: "Collection(Edm.Single)", searchable: true,
      vectorSearchDimensions: 384, vectorSearchProfileName: "default-profile" },
  ],
  vectorSearch: {
    algorithms: [{ name: "default-hnsw", kind: "hnsw" }],
    profiles: [{ name: "default-profile", algorithmConfigurationName: "default-hnsw" }],
  },
};

await client.createOrUpdateIndex(index);
console.log("doc-hierarchy-index ready.");
```
Only needs to be re-run if the index doesn't exist yet at all (fresh Azure resource) — not as
part of adopting this change.

## 4. `graph.ts`

Only the import and the one call site change:
```ts
import fs from "node:fs";
import path from "node:path";
import { getLatestBaselineDir } from "./baselines.js";

type Edge = { docId: string; dependsOn: string[] };

export async function loadGraph(): Promise<Edge[]> {
  const file = path.join(getLatestBaselineDir(), "manifest.json");
  return JSON.parse(await fs.promises.readFile(file, "utf-8"));
}

export function downstreamOf(graph: Edge[], changedDocId: string): string[] {
  const affected = new Set<string>();
  const queue = [changedDocId];
  while (queue.length) {
    const current = queue.shift()!;
    for (const doc of graph) {
      if (doc.dependsOn.includes(current) && !affected.has(doc.docId)) {
        affected.add(doc.docId);
        queue.push(doc.docId);
      }
    }
  }
  return [...affected];
}
```
Resolved fresh on every call rather than cached at module load — "latest" can change mid-session
if `ingest.ts` runs against a newly created baseline while the MCP server is still running.

## 5. `mcpServer.ts` — dynamic defaults for `list_documents` and `detect_change`

```ts
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";
import fs from "node:fs";
import path from "node:path";
import { loadGraph, downstreamOf } from "./graph.js";
import { detectChange } from "./detectChange.js";
import { resolveDocPath, getLatestBaselineDir, getLatestDraftDir } from "./baselines.js";

const RAG_API_URL = process.env.RAG_API_URL ?? "http://localhost:8000/search";
const INDEX = "doc-hierarchy-index";
const server = new McpServer({ name: "doc-hierarchy", version: "1.0.0" });

function odataEscape(s: string): string {
  return s.replace(/'/g, "''");
}

server.registerTool(
  "list_documents",
  {
    description: "List every document in the current baseline's graph and whether it changed in a draft. Defaults to the latest baseline and latest draft folders.",
    inputSchema: { draftDir: z.string().optional() },
  },
  async ({ draftDir }) => {
    const baselineDir = getLatestBaselineDir();
    const resolvedDraftDir = draftDir ? resolveDocPath(draftDir) : getLatestDraftDir();
    const graph = await loadGraph();
    const rows = graph.map(({ docId }) => {
      const baselineFile = path.join(baselineDir, `${docId}.docx`);
      const draftFile = path.join(resolvedDraftDir, `${docId}.docx`);
      const baselineExists = fs.existsSync(baselineFile);
      const draftExists = fs.existsSync(draftFile);
      if (!baselineExists || !draftExists) {
        return `${docId}: missing (${!baselineExists ? "baseline" : "draft"})`;
      }
      const same = fs.readFileSync(baselineFile).equals(fs.readFileSync(draftFile));
      return `${docId}: ${same ? "same" : "CHANGED"}`;
    });
    return { content: [{ type: "text" as const, text: rows.join("\n") }] };
  }
);

server.registerTool(
  "detect_change",
  {
    description: "Diff a document's baseline copy against its draft copy. Give baselinePath/draftPath to override; otherwise resolves docId against the latest baseline and latest draft folders.",
    inputSchema: { docId: z.string(), baselinePath: z.string().optional(), draftPath: z.string().optional() },
  },
  async ({ docId, baselinePath, draftPath }) => {
    const resolvedBaselinePath = baselinePath
      ? resolveDocPath(baselinePath)
      : path.join(getLatestBaselineDir(), `${docId}.docx`);
    const resolvedDraftPath = draftPath
      ? resolveDocPath(draftPath)
      : path.join(getLatestDraftDir(), `${docId}.docx`);
    const summary = await detectChange(resolvedBaselinePath, resolvedDraftPath);
    return { content: [{ type: "text" as const, text: summary ?? "No changes detected." }] };
  }
);

server.registerTool(
  "trace_impact",
  {
    description: "Given a changed document ID, return all documents downstream of it in the latest baseline.",
    inputSchema: { docId: z.string() },
  },
  async ({ docId }) => {
    const graph = await loadGraph();
    const affected = downstreamOf(graph, docId);
    return { content: [{ type: "text" as const, text: affected.length ? affected.join(", ") : "No downstream documents found." }] };
  }
);

server.registerTool(
  "suggest_changes",
  {
    description: "Suggest what might need updating in a downstream doc given an upstream change summary.",
    inputSchema: { docId: z.string(), changeSummary: z.string() },
  },
  async ({ docId, changeSummary }) => {
    const res = await fetch(RAG_API_URL, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        index: INDEX,
        query: changeSummary,
        top_k: 5,
        filter: `docId eq '${odataEscape(docId)}'`,
      }),
    });
    const { results } = (await res.json()) as { results: { content: string; source: string }[] };
    const text = results.length
      ? `Related passages in ${docId} that may need review:\n\n` + results.map(r => r.content).join("\n---\n")
      : `No related passages found in ${docId}.`;
    return { content: [{ type: "text" as const, text }] };
  }
);

server.registerTool(
  "notify_owner",
  {
    description: "Log a notification to a document's owner/reviewer (stub — wire up email/Teams later).",
    inputSchema: { docId: z.string(), message: z.string() },
  },
  async ({ docId, message }) => {
    console.error(`NOTIFY ${docId}: ${message}`);
    return { content: [{ type: "text" as const, text: "Logged (stub)." }] };
  }
);

const transport = new StdioServerTransport();
await server.connect(transport);
```
`suggest_changes`'s filter is unchanged from `003` (`docId eq '<escaped>'`) — no baseline clause
needed, since the index never holds more than one baseline's content at a time.

## 6. Migration checklist

Since `docs/` is gitignored, everything below is a local filesystem change on whatever machine
has the sample data — not something `git pull` will do for you.

1. Rename `docs/baseline1` → `docs/baseline-1`, `docs/draft2` → `docs/draft-1`.
2. Delete `current-baseline.txt` — nothing reads it any more.
3. Rename `currentBaseline.ts` → `baselines.ts`; update the three import sites
   (`ingest.ts`, `graph.ts`, `mcpServer.ts`).
4. Re-run `doc-hierarchy:ingest` — with the rename in step 1, this resolves to
   `docs/baseline-1` automatically, wipes any old-scheme entries out of the index on its own,
   reindexes, and writes `manifest.json`. No separate index drop/recreate step needed.
